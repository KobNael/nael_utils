Log utilities

Here you can find some tools for logging purpose :

  • The verbosity is defined with the enum Log level

  • Two loggers are available :

    • A basic Log file

    • TeeLogger, allowing to simultaneously print in the terminal and in a file

  • A Logger Manager is also provided

  • A Log session gives a thread its own loggers and settings (directory, verbosity, console), eg. for one run

  • Macros to log while taking the verbosity into account

A log file is created (and truncated) with its logger, unless the logger is created at level OFF: any file left by a previous use is then removed, and the file is only created on the first write (eg. after the level is raised). A logger which never writes creates no file.

The loggers and settings of the manager are stored in a Log state: the process wide one, or the one of the Log session alive on the calling thread.

Log session

Without session, the Logger Manager uses a process wide state: the log files are written in the current directory, and every thread shares the same loggers.

A LogSession gives the current thread its own state for its lifetime: log directory (created if needed), default verbosity, default log file name and console echo. Every call of the Logger Manager and every macro made on this thread uses it; its log files are closed when it ends, and the previous state of the thread is restored (sessions may be nested).

Sessions on different threads are independent, so several runs may log concurrently. As the log files are named after the loggers, give each run its own directory.

void run(std::filesystem::path const &log_dir)
{
    io::LogSession session(log_dir, io::LogLevel::INFO, "my_run", false);
    INFOLOG << "written to <log_dir>/my_run.log, not to the console" << std::endl;
    INFO(io::LoggerManager::GetFileLogger("detail")) << "written to <log_dir>/detail.log" << std::endl;
} // files closed, the thread is back to the process wide loggers

The jobs of a thread pool run with the session of the thread which enqueued them. Another thread joins a session with a LogSessionScope:

io::LogState *session = io::LoggerManager::CurrentSession();
std::thread worker([session]() {
    io::LogSessionScope scope(session);
    INFOLOG << "logged in the session of the parent thread" << std::endl;
});

Creating, getting and clearing the loggers of a state is thread safe (the threads of a pool share their state). Writing to one logger from several threads at once is not: use one logger per thread or job.

Warning

A thread started during a session without LogSessionScope uses the process wide state. The session must outlive the threads using it.
